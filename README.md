- Scientific computing and research software
- Infrastructure: clusters, storage, filesystems, and software environments
- Programming: Python, Bash, SQL, C/C++, R, and debugging just about any other language that can run on an HPC cluster
- Technical documentation

## 🔨 Things I Like Building

I like building tools that make HPC systems more intuitive and usable. While Slurm is great, it can be a challenge to, for example, track down historical accounting information for jobs or to get a sense of the scale and active usage of a cluster. I've written a number of [command line utilities](https://github.com/SaraMWillis/slurm-wrappers) to help users on our systems more easily track these sorts of things down. 

The `nodes-busy` CLI (a program used to visualize an HPC cluster's usage) in particular started out as a pet project just for me and has evolved into a system tool our researchers can use to visualize our clusters' status. I am always fantasizing about refactoring this code and creating a separate repository for it. Maybe someday, time permitting, I'll get around to it. 

## 🧭 Field Notes

## 🎓 Background

I earned my B.S. in physics and mathematics from The University of Arizona, then transitioned to bioinformatics following graduation. Working in scientific research (analyzing and managing large quantities of genomic data) is where I really learned to code and construct scientific pipelines. It was there that I found my particular interests were in debugging, installing stubborn software, and building programs. Transitioning to HPC consulting allowed me to stay in my preferred academic and science-oriented ecosystem while also working on the kinds of technical problems I find fascinating.
